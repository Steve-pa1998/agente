CONSENSUS

Consensus is the process by which a group of a nodes in a distributed system agree on a single value or decisión despite the potential for failures or inconsistencies

This is often used to make sure that all nodes reach an agreement on critcal descions such as: committing a transaction, chosing a configuration option, or agreeing on a specific value.

CONSENSUS ALGORITHMS typically require processes to communicate to propose and agree on values while also ensuring properties like SAFETY and LIVENESS

DATA REPLICATION WITH RAFT

Raft´s main use case is data replication it uses the concept of a state machine where all of the nodes start in the same state and by applying the same operations, in the same order, they all end up in the same state.

Each node in the system has a log of operations and a state which includes the actual data. WHen a client sends a request to store a file the leader adds this entry to his own log first before actually changing the state.

The leader then sends an AppendEntries message to all folower nodes which includes the new log entry.

Each follwer appends the receipt entry to its own log and sends an acknowledgement back to the leader.

Once the leader receives acknowledgement from a mjority of followers, it commits the entry.

COMMITTING
Means the entry is applied to the leader´s state.

For example, the file is saved.

Then the leader sends a message to the followers indicating the entry is comitted.

Followers then apply the entry to their own state.

This process ensures that all nodes maintain the same sequence of operations in their logs leading to a consistent state across the system.

Since we depend on the majority, several of the followers can fail and still work.

In Fact
Of we have 2F+1 followers up to F followers can fail.

When the leader fails, a new election is triggered.

and the new leader is chosen based on the highest log index to ensure no data is lost.

The new leader then continues to replicate entries from where the old leader left off.

IF A FOLLOWER FAILS

the leader Will keep on sending the appendEntries indefinitely until it gets confirmation.
